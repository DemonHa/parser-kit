# @parser-kit/sql

## 0.1.0

### Minor Changes

- [#104](https://github.com/DemonHa/parser-kit/pull/104) [`c4c83df`](https://github.com/DemonHa/parser-kit/commit/c4c83df3cf8b5fc79188e0a206d8d0fc39fdeaf6) Thanks [@DemonHa](https://github.com/DemonHa)! - Add `postgres.format(text, options?)`, a text-to-text formatter that keeps comments. It parses a psql script as `parseScript` does and prints it as `stringifyScript` does, taking the same options, and puts every comment back. A comment between statements stays where it was: after the statement's `;` when it starts on the line that statement ends on (unless a `--` comment is already there), otherwise on a line of its own. A comment inside a statement moves to just before that statement, as does any comment on a `COPY … FROM STDIN`'s line but the one `--` comment psql allows after its `;`. One blank line is kept where the source had any. Comments are copied verbatim, except that line endings are written `\n`: inside a block comment any run of CRs before an LF becomes `\n`, and CRs ending a `--` comment are dropped. `format` never changes meaning: the output parses back to the same items, spans aside. It keeps every comment's text and is idempotent. The formatter comes with the `postgres` object of the root and `@parser-kit/sql/postgres` entries, adding about 1 KB minified and gzipped. The parse-only `@parser-kit/sql/postgres/parser` entry doesn't include it. `FormatOptions` is exported from `@parser-kit/sql/postgres`. Parsing is unchanged: the parse lexers report the comments they skip only while `format` runs, and the AST holds none.

- [#79](https://github.com/DemonHa/parser-kit/pull/79) [`0f24cc2`](https://github.com/DemonHa/parser-kit/commit/0f24cc20cb326e25fba97de9728612c4bb4e311d) Thanks [@DemonHa](https://github.com/DemonHa)! - First release of `@parser-kit/sql`: the PostgreSQL 17 grammar that lived in the repo as the `examples/sql-lite` example, now published as a package with a dialect-first API. `postgres.parse(sql)` parses SQL into a span-annotated `Stmt[]` and throws a `ParseError` at the first problem; `postgres.diagnose(sql)` recovers at each `;` and returns `{ ast, errors }`. `postgres.parseScript(text)` and `postgres.diagnoseScript(text)` read whole psql / pg_dump scripts into `ScriptItem[]`, meta-command lines and `COPY … FROM stdin` data included. `postgres.lexer` and `postgres.scriptLexer` tokenize SQL with comments kept, for highlighters. `@parser-kit/sql/postgres` exports the `postgres` object with the AST types (`Stmt`, `Query`, `Expr`, `ScriptItem`, …), `PostgresDialect`, `PostgresTokenType` and `Diagnosis`. The package root exports the same object and types, with the AST types namespaced as `Postgres.Stmt` and so on, so that later dialects (each with its own subpath) can sit beside it without name clashes. Ships as dual ESM/CommonJS with type declarations, and depends on `@parser-kit/core`.

- [#102](https://github.com/DemonHa/parser-kit/pull/102) [`f14acc9`](https://github.com/DemonHa/parser-kit/commit/f14acc9fc451540518df0066a0d525073ac2f48e) Thanks [@DemonHa](https://github.com/DemonHa)! - Add `postgres.stringify` and `postgres.stringifyScript`, which print an AST back as PostgreSQL. `stringify(node, options?)` takes what `postgres.parse` returns, a single statement, an expression or a type, parsed or built by hand, and returns canonical SQL that parses back to the same tree (with `semicolons: "never"`, one statement at a time). By default each statement is written on one line, ended by `;`, with upper-case keywords and names quoted only where they must be. The options are `width` (default `Infinity`; a number such as `80` lays the output out to fit), `indent` (`2`, or a string such as `"\t"`), `keywordCase` (`"upper"` / `"lower"`), `identifierQuote` (`"minimal"` / `"always"`), `semicolons` (`"always"` / `"between"` / `"never"`) and `strings` (`"standard"` / `"escape"`). `stringifyScript(items, options?)` prints `postgres.parseScript`'s items back as a psql script, with meta-command lines and each `COPY … FROM stdin`'s rows. Comments are not kept. `@parser-kit/sql/postgres` also exports the `StringifyOptions`, `StringifyScriptOptions`, `StringifyInput` and `StringifyScriptInput` types, and `NotPrintableError`, which the package root exports too, with the new `PostgresParser` type.
  
  The printer comes with the `postgres` object of the root and `@parser-kit/sql/postgres` entries, about 26 KB minified and gzipped on top of the parser's 57 KB, since an object's methods can't be tree-shaken apart. Bundles that only parse can import the new `@parser-kit/sql/postgres/parser` entry instead: the same object without the printer (typed `PostgresParser`), with the same AST types.

### Patch Changes

- [#85](https://github.com/DemonHa/parser-kit/pull/85) [`8309ba8`](https://github.com/DemonHa/parser-kit/commit/8309ba8c01d6b7c3819e020811fafbc45f0711a3) Thanks [@DemonHa](https://github.com/DemonHa)! - Keep qualified-name parts and numeric literal text in the AST. A call's `name`, a type's `name`, a `RANGE` option's `value` and a configuration parameter's name (`SET` / `SHOW` / `RESET`, `ALTER ROLE` / `ALTER DATABASE … SET | RESET`, and `parameter` on a routine's `SET`) are now `string[]` with one element per part, so `"a.b"(1)` (`["a.b"]`) and `a.b(1)` (`["a", "b"]`) no longer parse to the same tree. A quoted type name that spells a multi-word type (`"double precision"`) carries `quoted: true`. A number now keeps `raw` whenever its decimal text is anything but the plain integer `String(value)` gives back (`1.0`, `1.50`, `5.`, `1e2`), so its PostgreSQL type (`numeric` vs `integer`) and scale survive; a `0x` / `0o` / `0b` integer below 2^53 still has none. Breaking for code written against the `examples/sql-lite` shapes that reads these fields as strings.
