Add `postgres.stringify` and `postgres.stringifyScript`, which print an AST back as PostgreSQL. `stringify(node, options?)` takes what `postgres.parse` returns, a single statement, an expression or a type, parsed or built by hand, and returns canonical SQL that parses back to the same tree. By default each statement is written on one line, ended by `;`, with upper-case keywords and names quoted only where they must be. The options are `width` (default `Infinity`; a number such as `80` lays the output out to fit), `indent` (`2`, or a string such as `"\t"`), `keywordCase` (`"upper"` / `"lower"`), `identifierQuote` (`"minimal"` / `"always"`), `semicolons` (`"always"` / `"between"` / `"never"`) and `strings` (`"standard"` / `"escape"`). `stringifyScript(items, options?)` prints `postgres.parseScript`'s items back as a psql script, with meta-command lines and each `COPY … FROM stdin`'s rows. Comments are not kept. `@parser-kit/sql/postgres` also exports the `StringifyOptions`, `StringifyScriptOptions`, `StringifyInput` and `StringifyScriptInput` types and `NotPrintableError`, which the package root exports too.

The printer comes with the `postgres` object of the root and `@parser-kit/sql/postgres` entries, about 26 KB minified and gzipped on top of the parser's 57 KB, since an object's methods can't be tree-shaken apart. Bundles that only parse can import the new `@parser-kit/sql/postgres/parser` entry instead: the same object without the printer (typed `PostgresParser`), with the same AST types.
