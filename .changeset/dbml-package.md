First release of `@parser-kit/dbml`, a typed DBML parser built on `@parser-kit/core`. `dbml.parse(text)` parses a DBML document into a span-annotated `DbmlDocument` and throws a `ParseError` at the first error; `dbml.diagnose(text)` recovers at each settings list, body line and top-level element, and returns `{ ast, errors }` with every error it finds. It reads the DBML language as `@dbml/core` 12 does: `Project`, `Table` (schemas, aliases, settings, custom properties, column types and settings, notes), `Ref` in short, long and inline form with optional sides and composite endpoints, `Enum`, `indexes` and `checks`, `TableGroup`, sticky notes, `TablePartial` with `~partial` injection, and `records`. Keywords are case-insensitive and contextual, so they stay usable as names. `dbmlLexer` tokenizes DBML with comments kept, for highlighters, and every AST node type is exported. The package parses only: it doesn't resolve names, merge partials or validate. The README lists the deliberate differences from `@dbml/core` and what isn't supported yet (`DiagramView`, `Dep`, `Metadata`, `use` / `reuse`). Ships as dual ESM/CommonJS with type declarations, and depends only on `@parser-kit/core`.
